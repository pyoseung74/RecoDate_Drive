# RecoDate Drive 설계안 (Pleos Connect 차량용)

작성: 2026-10-30 · 대상: 현대자동차그룹 차량용 앱 개발 공모전 (마감 2026-11-15)

## 1. 목표

차 안에서 **고민 없이, 빠르게** 목적지 주변의 장소와 코스를 추천한다.
입력은 탭 2~3번 이내로 끝낸다. 주행 중에는 텍스트 입력을 받지 않는다.

추천할 때 함께 따지는 요소:

- 주차장 혼잡도 (실시간 정보가 있으면 사용, 없으면 예측)
- 차 막힘 수준 (도착 예정 시간)
- 날씨 (비, 기온)
- 차량 에너지 (전기차 배터리, 연료 잔량)

## 2. 코스 모드 2가지

| 모드 | 이런 사람에게 | 구성 방식 |
|---|---|---|
| **한 번 주차 (도보형)** | 한곳에 차를 세우고 걸어서 돌고 싶음 | 목적지 근처 주차장 1곳 → 걸어서 장소 3~4곳 → 주차장으로 복귀. 총 도보 2km 이하, 주차장에서 장소까지 700m 이하 |
| **차로 이동 (차량형)** | 걷는 걸 최소화하고 싶음 | 장소마다 가까운 주차장(장소에서 200m 이내)을 붙인다. 장소 사이는 차로 이동한다. 장소들은 목적지 기준 반경 10km 이내 |

기본값은 자동으로 정한다. 비가 오거나 기온이 영하 이하 또는 33℃ 이상이면 차량형, 그 밖에는 도보형으로 한다.
사용자는 버튼 하나로 바꿀 수 있다.

## 3. 화면 흐름 (3단계)

1. **출발 화면**: 목적지 고르기
   - 내비에 이미 목적지가 설정돼 있으면 그 목적지 (`NaviHelper.getDestinationInfo`)
   - 최근 목적지와 즐겨찾기 (`getRecentDestinationInfo`, `getBookmarkInfo`)
   - "지금 내 주변" (`getCurrentLocationInfo`)
   - 정차 중(P단)에만: 프리셋 지역 칩 + 검색
   - 선택 칩(한 번 탭): 식사 / 카페 / 산책 / 실내 / 액티비티
2. **추천 화면**: 코스 카드 3개
   - 카드마다: 주차장과 혼잡도, 도착 예정 시간(교통 반영), 날씨 배지, 총 도보 거리, 장소 순서
3. **실행 화면**: "안내 시작"
   - 도보형: 주차장을 내비 목적지로 설정 (`requestRoute`)
   - 차량형: 첫 장소의 주차장을 목적지로 설정. 도착하면(`onDestinationArrived`) 다음 장소의 주차장을 이어서 설정
   - 하차 시점(기어 P 전환 + 도착 이벤트)에 QR을 띄운다. 폰으로 찍으면 남은 코스를 볼 수 있다 (2단계 범위)

## 4. 주행 중 제한 (운전자 주의 분산 가이드라인)

- 기어가 P가 아니면 주행 중으로 본다. 기어는 `Vehicle.getGear().registerGearSelection`으로 받는다. 시스템의 `CarUxRestrictions`도 함께 확인한다.
- 주행 중에는 큰 버튼만 보여 준다: "추천 받기", "안내 시작", "다음 장소". 검색, 코스 편집, 긴 목록은 잠근다.
- 애니메이션과 자동 화면 전환은 쓰지 않는다. 터치 영역은 크게, 대비는 높게 한다.

## 5. 데이터 출처

| 요소 | 1순위 | 대체 (키 없음, 오프라인) |
|---|---|---|
| 현재 위치 | NaviHelper `getCurrentLocationInfo` | FusedLocation (SDK 상태 "준비 중") → 마지막 목적지 |
| 장소 후보 | TMAP 주변 POI 검색 (전국) | 내장 샘플 데이터 (데모용) |
| 주차장 | 공공데이터 전국주차장정보표준데이터 + TMAP POI(주차장) | 내장 샘플 |
| 주차 혼잡도 | 한국교통안전공단 실시간 주차정보 (지원 지역만) | 예측: 시간대, 요일, 주차면 수, 주변 장소 밀도 |
| 교통 / 도착 예정 시간 | TMAP 자동차 경로 (실시간 교통 반영) | 거리 ÷ 시간대별 평균 속도 |
| 내비 경로의 교통 | NaviHelper `RouteStateInfo.trafficStatus`, `DestinationInfo.remainTime` | - |
| 날씨 | 기상청 단기예보 (강수형태, 강수확률, 기온) | "정보 없음"으로 표시하고 감점하지 않음 |
| 에너지 | Vehicle `getEvBattery().getEvBatteryStateOfCharge`, `getFuel().getFuelPercent` | 정보 없음 → 무시 |

API 키는 `local.properties`에 넣고 BuildConfig로 읽는다. 키가 없으면 해당 데이터 출처를 가짜 구현으로 바꾼다. 그래서 키 없이도 에뮬레이터 시연이 가능하다.

## 6. 추천 알고리즘

입력: 목적지 좌표, 모드, 선택 칩, 현재 시각, 날씨, 에너지, 현재 위치

1. **후보 수집**: 목적지 반경 안의 장소(카테고리별)와 주차장을 모은다. 반경은 도보형 1km, 차량형 10km.
2. **장소 점수**
   - 칩과 맞는 카테고리: +3
   - 비 또는 혹서·혹한일 때: 실내 +2, 실외 −3
   - 영업시간 정보가 있으면 반영한다 (TMAP POI 상세)
3. **주차장 점수** (0~1, 높을수록 좋음)
   - 혼잡도(실시간 또는 예측) 50%, 장소까지 거리 30%, 요금 20%
   - 혼잡도 "매우 혼잡"(예상 점유율 90% 이상)은 제외한다. 후보가 없으면 경고와 함께 유지한다.
4. **코스 만들기**
   - 시간대별 틀: 점심 → 식사·카페·산책 / 오후 → 액티비티·카페·식사 / 저녁 → 식사·산책·카페
   - 도보형: 주차장 후보 상위 5곳마다 도보 반경 안에서 틀의 칸을 채운다. 순서는 주차장에서 출발해 돌아오는 순환 경로 중 가장 짧은 것(장소 4곳 이하, 완전 탐색).
   - 차량형: 칸마다 "장소 + 그 장소의 주차장" 쌍을 고른다. 순서는 현재 위치에서 출발하는 차량 이동 시간 합이 가장 짧은 것.
   - 코스끼리 장소가 겹치면 감점해서 3개 코스를 다르게 만든다.
5. **교통 반영**: 최종 후보 코스(최대 6개)의 첫 주차장까지 TMAP 경로 ETA를 조회한다. 도착 예정 시간을 점수에 넣는다.
6. **에너지 반영**: 배터리나 연료가 15% 이하이고 총 주행 거리가 주행 가능 거리의 70%를 넘으면 경고한다. 충전소나 주유소를 경유지로 제안한다.

엔진은 Android에 의존하지 않는 순수 Kotlin으로 만들고 단위 테스트한다.

## 6-1. Codex 검토 후 정한 규칙 (2026-10-30)

- **목적지의 역할**: 내비 목적지, 최근 목적지처럼 이름이 있는 기준점은 코스에 꼭 넣는다. "지금 내 주변"은 검색 중심점으로만 쓴다.
- **점수 공식**: 모든 항목을 0~1로 맞춘 뒤 가중합한다.
  - 장소 = 0.5 관심사 + 0.3 날씨 + 0.2 인기도(모르면 0.5)
  - 주차장 = 0.5 (1−혼잡도, 모르면 0.5) + 0.3 가까움 + 0.2 요금(모르면 0.5)
  - 코스 = 0.4 장소 평균 + 0.3 주차장 + 0.3 시간 적합 − 0.1 도보 부담
  - 동점이면 총 이동이 짧은 코스, 그다음 id 순
- **거리**: 직선거리에 우회 계수를 곱해 실제 거리를 어림한다 (도보 1.3배, 차량 1.4배).
- **후보 부족**: 장소 수를 최소 2곳까지 줄인다. 카드에 "장소가 적어 N곳으로 줄였어요"라고 표시한다.
- **모드 자동 전환**: 사용자가 직접 고르지 않았을 때만, 날씨가 나쁘면 차로 이동형으로 바꾼다. 날씨 정보가 없으면 바꾸지 않는다.
- **에너지**: 퍼센트만으로 주행 가능 거리를 계산하지 않는다. 15% 이하이면 경고하고 가장 가까운 충전소·주유소만 알려 준다.
- **API 호출 줄이기**: 차로 이동형 검색 반경은 6km로 한다. 교통 경로 조회는 최종 코스(최대 3개)의 첫 목적지까지만 하고, 5분 동안 캐시한다.
- **주차 혼잡도**: 실시간 정보가 없으면 "예상"이라고 표시한다. 근거는 시간대·요일, 주변 장소 수, 주차면 수, 무료 여부다.

## 7. 코드 구조

```
RecoDate_Pleos/
  app/src/main/java/com/recodate/drive/
    MainActivity.kt          Compose 진입점
    ui/                      출발, 추천, 실행 화면 + 주행 중 제한 상태
    vehicle/                 VehicleGateway (Pleos 구현 + 가짜 구현)
    navi/                    NaviGateway (Pleos NaviHelper 구현 + 가짜 구현)
    data/                    PlaceSource, ParkingSource, TrafficSource, WeatherSource
                             (TMAP, 공공데이터, 기상청 구현 + 가짜 구현)
    engine/                  CourseRecommender, ParkingScorer, RouteOrderer (순수 Kotlin)
    model/                   데이터 클래스
  app/src/test/              엔진 단위 테스트
```

- minSdk 28, compile/targetSdk 34 (에뮬레이터 API 34)
- Kotlin + Jetpack Compose, Coroutines, OkHttp + kotlinx.serialization
- Pleos SDK: Vehicle 2.3.2, NaviHelper 3.0.5 (둘 다 신청 없이 사용 가능)
- FusedLocation, TTS, STT는 "준비 중"이라 선택 기능으로 두고, 없어도 동작하게 만든다.

## 8. 범위 밖

- 회원가입, 커뮤니티, 채팅, 리뷰, TripTI
- 대중교통
- 서버 (앱이 외부 API를 직접 호출)

## 9. 확인이 필요한 점

- Pleos Connect 앱이 외부 인터넷(TMAP, 공공데이터)을 쓸 수 있는가. 공식 문서에 명시가 없다. 아키텍처 문서는 "네트워크가 끊길 때에 대비하라"고만 한다. 대비책으로 가짜 데이터와 캐시를 둔다.
- 실시간 주차정보 API가 지원하는 지역의 범위.
- 에뮬레이터에서 NaviHelper가 실제로 경로 안내까지 하는지 (Virtual Console로 확인).
